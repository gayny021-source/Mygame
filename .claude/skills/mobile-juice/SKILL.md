# Тактильная отдача и ощущение игры на телефоне

Справочник для агентов. Готовый код — `examples/juice.gd` (класс `Juice`).

> **Проверено на Godot 4.7.2 (2026-11-07).**
> - `juice.gd` разбирается и работает в headless; все сценарии поломки из раздела 1
>   прогнаны и дают исход из таблицы.
> - `CPUParticles2D` с `one_shot` запускается.
> - Сигнатура проверена по ClassDB: `Input.vibrate_handheld(duration_ms: int = 500,
>   amplitude: float = -1.0)`.
> - Ощущение (вес, отклик) headless не проверить: только на устройстве.

**Сначала столпы.** «Бросок — это событие»: главная отдача игры — это бросок d20 и
исход проверки. Боёв нет (анти-столп), так что «отдача оружия» и «попадание» здесь
значат:

- толчок кубика при падении;
- вздрагивание карточки героя на провале;
- россыпь искр на критическом успехе.

Отдача не должна тормозить чтение. Анимация кнопки варианта короче 0,3 с, а длинная
пауза бывает только у броска (в прототипе ~2,3 с).

## 1. Tween-паттерны (`create_tween()`)

| Функция `Juice` | Что делает | Где в игре |
|---|---|---|
| `press_bounce(control)` | сжатие до 0,92 за 0,06 с, отскок `TRANS_BACK` за 0,25 с (через `offset_transform_scale`) | `button_down` у вариантов и кнопок меню |
| `pop_in(control)` | появление: прозрачность 0 → 1, масштаб 0,85 → 1 с перелётом | окно броска, эпилог, карточка героя |
| `punch(node2d, dir)` | толчок по направлению и упругий возврат `TRANS_ELASTIC` (это и «отдача оружия») | кубик при падении, иллюстрация на ударе |
| `shake(item)` | затухающая тряска на 6 шагов (Control — `offset_transform_position`, Node2D — `position`) | провал или критический провал, только очень коротко |
| `finish(node)` | сразу в покой: пропуск анимации, «меньше анимации» | настройка, кнопка «пропустить» |

Правила, которые держит `juice.gd` (каждое проверено в 4.7.2 headless):

- **Один Tween на ноду, и прерывание — в покое.** Новый помощник сначала вызывает
  `Juice.finish(node)`: убивает прежний Tween и возвращает ноду в покой. `Tween.kill()`
  сам по себе оставляет свойство на полпути (проверено: прозрачность застыла на 0,2).
  Без `finish()` кнопка осталась бы полупрозрачной или сдвинутой.
- **Control анимируется через `offset_transform_*`** (новое в 4.7,
  `current-best-practices.md`). Это визуальное смещение, которое контейнеры не
  сбрасывают; прямоугольник раскладки и глобальная трансформация при нём не меняются
  (проверено). Точка опоры по умолчанию — центр (`offset_transform_pivot_ratio`).
  Покой всегда «смещение 0, масштаб 1», поэтому повторная тряска не уплывает.
- **Node2D** (кубик, спрайт карточки) анимируется через `position`. Исходная позиция
  берётся после `finish()`, так что два `punch` подряд возвращают кубик ровно домой.
- **Tween привязан к ноде** (`node.create_tween()`): после `queue_free()` он
  недействителен, ошибок нет (проверено).
- **Вне дерева помощники ничего не делают.** `pop_in` до `add_child` просто
  показывает ноду в покое, без анимации.
- **Juice владеет свойствами, которые анимирует:** `modulate.a` и `offset_transform_*` у
  Control, `position` у Node2D. Пока идёт анимация, игра эти свойства сама не трогает.
  Нужно затемнить или сдвинуть такую ноду — делай это через дочернюю ноду.
- **Анимация не управляет логикой.** Исход проверки применяется сразу, анимация только
  показывает его. Ввод блокирует Система выбора, а не «пока идёт Tween».
- **Всё отключаемо.** Настройка «меньше анимации» и «пропустить анимацию» вызывают
  `Juice.finish(node)` (`.claude/rules/ui-code.md`: «All animations must be
  skippable»).

### Сценарии поломки (исход проверен в 4.7.2 headless, `juice.gd`)

| Сценарий | Исход |
|---|---|
| спам тапами по кнопке с `press_bounce` | анимации не копятся, кнопка приходит к масштабу 1 |
| `shake` дважды подряд по Control | смещение возвращается к 0, раскладка не меняется |
| `punch` во время `punch` по Node2D | позиция возвращается ровно в исходную |
| `punch` с `dir = Vector2.ZERO` | ничего не происходит (`normalized()` нулевого вектора даёт 0, NaN нет) |
| `press_bounce` прерывает `pop_in` | прозрачность 1, масштаб 1 |
| `finish()` посреди анимации | нода сразу в покое |
| нода удалена посреди анимации | Tween недействителен, ошибок нет |
| `pop_in` до `add_child` | нода видна, прозрачность 1 |
| вызов помощника после `await` на удалённой ноде | **проверяет вызывающий**: `is_instance_valid(node) and node.is_inside_tree()` |
| другой Tween на ту же ноду | только после `Juice.finish(node)` |
| кубик переставили в другую точку после законченного `punch`, потом снова `punch` | кубик остаётся в новой точке: покой восстанавливается только для идущего Tween |
| карточку затемнили до 0,5 после законченного `pop_in`, потом `press_bounce` | прозрачность остаётся 0,5 |
| сворачивание приложения посреди Tween | конечные значения абсолютные, логика от Tween не зависит. Уведомления жизненного цикла (проверено ClassDB 4.7.2): `NOTIFICATION_APPLICATION_PAUSED` = 2015, `_RESUMED` = 2014, `_FOCUS_OUT` = 2017, `_FOCUS_IN` = 2016, кнопка «Назад» — `NOTIFICATION_WM_GO_BACK_REQUEST` = 1007 |

На устройстве ещё проверить:
- тап у самого края кнопки во время «пружинки»;
- касание варианта, который ещё проявляется, с переходом в прокрутку.

## 2. Частицы попаданий и критов

- **По умолчанию `CPUParticles2D`.** В рендерере Compatibility (наш, `project.godot`) это
  самый предсказуемый путь, а для 20–40 искр CPU хватает. `GPUParticles2D` в 4.7.2 есть
  (ClassDB), но как он работает на Compatibility на целевых телефонах, в
  `docs/engine-reference/godot/` не описано: это `NOT SOURCEABLE`, проверять на
  устройстве.
- **Разовая вспышка.** Рецепт проверен в 4.7.2:
  - `one_shot = true`, `explosiveness = 1.0`;
  - `amount` 16–32, `lifetime` 0,4–0,6 с;
  - `spread = 180`, `initial_velocity_min` / `max` 120 / 260;
  - `gravity = Vector2(0, 400)`, `scale_amount_min` / `max` 2 / 4;
  - запуск — `restart()`.
- **Текстура частицы** — маленький SVG (звёздочка, клякса) из скилла
  `procedural-art-sfx`, а не квадрат по умолчанию.
- **Бюджет.** Одна вспышка на событие. Не больше двух эмиттеров на экране одновременно.
  Draw calls ≤ 100 (`project.yaml` → `performance`).

## 3. Вибрация (`Input.vibrate_handheld`)

```gdscript
Juice.buzz(settings.haptics_enabled, 30)        # тап по варианту: 20–30 мс
Juice.buzz(settings.haptics_enabled, 80, 0.8)   # критический успех / провал
```

- **Только на критических событиях:** результат броска, натуральные 1 и 20, конец главы.
  Не на каждый тап и не на скролл.
- **Коротко:** 20–80 мс. Длительность по умолчанию в движке — 500 мс, это слишком много:
  всегда передавай свою.
- `amplitude` от 0 до 1; `-1` — сила по умолчанию устройства.
- **Разрешение.** В пресете экспорта Android ставь `permissions/vibrate=true` (шаблон в
  скилле `godot-apk-ci`). Что будет без него — тишина или ошибка, — в
  `docs/engine-reference/godot/` не описано: `NOT SOURCEABLE`. Проверить на устройстве.
- **Выключатель в настройках** обязателен (система «Настройки», Alpha). До неё —
  константа в данных, не в коде.
- `Juice.buzz` молча ничего не делает вне Android и iOS, поэтому на ПК и в тестах не
  мешает.
