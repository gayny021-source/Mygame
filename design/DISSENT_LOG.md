# Журнал особого мнения инквизиции (Dissent Log)

Здесь хранятся замечания аудиторов (`godot-mobile-auditor`, `lore-inquisitor`) и
QA-агентов (`chaos-monkey`, `mobile-ux-validator`, `balance-simulator`,
`gut-test-engineer`), которые профильный директор отклонил через `[DIRECTOR OVERRIDE]`,
в том числе отложенные исправления критических багов. Ни одно особое мнение не
теряется: если решение директора потом аукнется, здесь видно, кто предупреждал и о чём.

- **Кто пишет.** Аудиторы работают только на чтение, поэтому запись от их лица вносит
  главный оркестратор (или директор) сразу после закрытия спора. Текст претензии — слова
  самого аудитора из его последнего отчёта: оркестратор их не смягчает и не дописывает.
- **Пара.** У каждой записи есть ответ директора в `design/DIRECTOR_DECISIONS.md`
  (запись `DD-NNN`), а там стоит ссылка обратно (`DS-NNN`).
- **Правило:** `CLAUDE.md`, раздел «Журналы решений».

## Как писать запись

- Новые записи добавляются в конец раздела «Записи», номера идут подряд: `DS-001`, `DS-002`…
- Сарказм — это подача, а не замена сути: в претензии остаются файл, нарушенное правило
  и риск. Без мата.
- Решения пользователя из `USER_PREFERENCES.md` вето не отменяет, поэтому такие споры
  сюда не попадают.
- Записи не удаляются и не правятся задним числом. Если решение потом пересмотрели,
  в конец записи добавляется строка `**Итог (дата):** …`.

Шаблон:

```markdown
### DS-NNN · [о чём спор, 3–6 слов]

- **Дата / Задача / Файл:** ГГГГ-ММ-ДД / [задача или навык] / `путь:строка` или раздел
- **Кто возражал:** `@godot-mobile-auditor` | `@lore-inquisitor` | `@chaos-monkey` |
  `@mobile-ux-validator` | `@balance-simulator` | `@gut-test-engineer`
- **Кто продавил вето:** `@technical-director` | `@narrative-director` | `@creative-director`
- **Суть претензии:** [голосом ворчливого, саркастичного перфекциониста: что не
  понравилось, какое правило нарушено и почему решение директора рискованное; например,
  «Я предупреждал, что этот узел просадит FPS на мобилках» или «Директор оставил эту
  реплику, хотя от неё веет дешёвым пафосом. Умываю руки»]
- **Вердикт Директора:** [коротко, почему замечание отклонено: «в угоду геймплею»,
  «ради динамики сцены», «сроки прототипа»]
- **Ответ Директора:** `design/DIRECTOR_DECISIONS.md`, DD-NNN
```

## Записи

### DS-001 · S5: заготовки O-18, обёртка diff, формат released_at

- **Дата / Задача / Файл:** 2026-11-16 / история S5 (ADR-0001, смысловые проверки и CLI), аудит раунд 2 / `src/core/story/validation/validator_options.gd:62-77`, `src/core/story/validation/released_ids.gd:34-39`, `tools/validate_data.gd:136-143`
- **Кто возражал:** `@godot-mobile-auditor`
- **Кто продавил вето:** `@technical-director`
- **Суть претензии:**
  - G1: «Поля frames/characters/ending_frames читаются только тестами; конфиг их не задаёт, O-18 открыт. Держать заготовку до O-18 — нарушение Lean §1. Тесты можно перевести на вход без полей.»
  - G2: «Снимок типизирован и покрывает CLI. Обёртка diff — вызов только из тестов, это обёртка под один вызов (Lean §1). Переписать released_ids_test на read + compare.»
  - G3: «load_file — I/O в validation/ и мёртвый для CLI код. Правило ADR:241 не даёт читать файлы в проверках. Перенести в тест или в ChapterLoader.»
  - C4: «C4 не выполнено по тексту TD: released_at общий на файл, а не по id; TD требует ответа по формату · TD решает: либо правка формата, либо письменное решение TD.»
- **Вердикт Директора:** тесты S5 написаны до кода и на эти места опираются; переписывать их ради чистоты дороже, чем держать немного кода под пересмотр. `load_file` объявлен загрузчиком опций в ADR; дата заморозки остаётся одной на файл.
- **Ответ Директора:** `design/DIRECTOR_DECISIONS.md`, DD-018

### DS-002 · S5: суррогатные пары в ключах JSON

- **Дата / Задача / Файл:** 2026-11-16 / история S5, аудит раунд 2 / `src/core/story/validation/json_lint.gd:126-127`
- **Кто возражал:** `@chaos-monkey`
- **Кто продавил вето:** `@technical-director`
- **Суть претензии:** «Суррогатная пара не склеивается: "😀" и "😀" считаются разными ключами. Поведение char() для суррогатов и отрицательных значений (is_valid_hex_number допускает знак) NOT SOURCEABLE — не описано в docs/engine-reference/godot/. Ключи ASCII, JSON.parse такие файлы всё равно отклоняет, поэтому вред мал.»
- **Вердикт Директора:** ключи данных по ADR-0001 только ASCII; файл с такой парой не проходит разбор и без линтера. Декодер UTF-16 в линтере — лишний код.
- **Ответ Директора:** `design/DIRECTOR_DECISIONS.md`, DD-019
