## Overview

Ветвящаяся история знает, из каких сцен состоит глава героя и куда из каждой сцены можно попасть. Глава — граф без циклов примерно из 12 сцен: хребет из узловых сцен и вдохов, через который проходит любой путь, одно ответвление на 1–2 сцены и, начиная со второй главы, свой вход для каждого итога прошлой главы (цель исполнена или провалена). У сцены есть текст, иллюстрация и от одного до четырёх вариантов. Вариант кончается исходом: текст ветки, флаги и переход. Каждый переход в сцену несёт мост — переходный абзац; переход в конец главы несёт коду с фразой-зацепкой. Финальный узел даёт три финала главы и четвёртый, который открывают только прошлые решения. Редкий провал может закончить прохождение раньше: это настоящая концовка, после которой схема главы позволяет начать новую попытку с пройденной узловой сцены. Система сама ничего не бросает, не считает и не ставит флаги. Она хранит данные сцен (поля здесь, формат файлов — отдельный ADR), отвечает на вопрос «что показать и куда идти дальше» и проверяет граф: нет тупиков, нет фальшивых выборов, каждая сцена достижима, пути укладываются в бюджет проверок и слов. Так держатся столпы «Решения имеют вес» (у каждого выбора есть читаемый след) и «Провал — это подарок» (провал ведёт в написанное продолжение или в настоящую концовку, а не в «загрузить»). В прототипе 4 проверки на 5 экранах без переходов читались как разрозненные скетчи (`prototypes/critical-fail-concept/REPORT.md`).

## Detailed Design

### Core Rules

> **НП-N** — правила текста глав `narrative-director`, лежат в `design/narrative/chapter-writing-rules.md` (вычитка `lore-inquisitor`). Коды **BS-NN** — проверки графа и данных (сборка, вычитка). Ранняя смерть и схема главы — с Vertical Slice: глава MVP без ранней смерти (решение Зама 2026-11-13, порядок работ; механику утвердил владелец).

1. **Словарь** (термины НП, раздел 1, в структурном смысле).
   - **Сцена** — узел графа: текст и один выбор. **Исход** — то, чем кончается вариант (текст, флаги, переход); узлом графа он не считается (подтверждение НП, раздел 13, п. 3).
   - **Хребет** — сцены, через которые проходит любой путь главы от первой общей сцены после входа. **Узловая сцена** (узел НП-12) — сцена хребта с полем `узловая`. **Вдох** — сцена хребта без рискованного варианта (НП-17). **Ответвление** — сцены вне хребта, кроме вариантов входа.
   - **Переход** — ребро графа: куда идти и какой текст показать на стыке. **Мост** — переходный абзац перехода в сцену (НП-8). **Кода** — текст перехода в конец главы (НП-50).
   - **Финал главы** — терминальный исход финального узла или открытого финала (правило 10). **Концовка** — конец прохождения. **Ранняя концовка** — концовка раньше финала (правило 11).
   - **Попытка** — отрезок прохождения от начала главы или от точки возврата до концовки.

2. **Глава.** Поля:

   | Поле | Правило |
   |---|---|
   | `id` | `^[a-z][a-z0-9_]*$`; входит в `главы` ровно одного героя (`heroes.md`, правило 1) |
   | `заголовок` | короткая подпись |
   | `цель` | одна формулировка (НП-19); показ и маркер — Цель главы |
   | `старты` | упорядоченный список `{если?, сцена}`; последняя запись без `если`. В первой главе героя запись одна. В следующих — по записи на итог прошлой главы (решение владельца 2026-11-13). Условия читают только флаги области `run`: флаги `chapter` к этому моменту сняты (`run-state.md`, правило 11) |
   | `флаг_провала_цели` | необязательно: `id` флага категории `story` с областью `run`. Его ставит исход, которым цель провалена; его читают Цель главы и `старты` следующей главы |
   | `сцены`, `исходы`, `переходы` | записи правил 3, 5, 6; `id` уникален в данных героя |

   Форма главы (BS-10): хребет; ровно одно ответвление размера `B`, которое выходит из одной сцены хребта и возвращается на хребет; каждый вариант входа — одна сцена, которая ведёт в первую общую сцену; ровно один финальный узел. Размеры — Formulas, F1.

3. **Сцена.** Поля:

   | Поле | Правило |
   |---|---|
   | `id` | `^[a-z][a-z0-9_]*$`, уникален в данных героя |
   | `заголовок` | необязательно |
   | `абзацы` | упорядоченный список абзацев (правило 7), хотя бы один без условия |
   | `иллюстрация` | `id`, обязательно; у разных сцен может совпадать (фоны переиспользуются, Иллюстрации сцен) |
   | `варианты` | от 1 до `OPTIONS_MAX` (F4) |
   | `веха` | необязательно: `id` вехи цели. Маркер строится по вехам, а не по доле пройденных сцен; по любому пути вехи не убывают (НП-11, НП-22). Предварительно, до GDD «Цель главы» |
   | `узловая` | необязательно: сцена хребта, точка возврата (правило 11) и место жетона (Vertical Slice; `USER_PREFERENCES.md`, «Проверки d20») |
   | `финал` | у ровно одной сцены главы: финальный узел, «начало финала» для Жетонов |

   - **Одна сцена — один выбор.** Все варианты видны одновременно; второй выбор — это следующая сцена.
   - **Порядок показа:** мост перехода, которым вошли (правило 6), затем `абзацы` в порядке записи (порядок слотов — НП-1). У стартовой сцены моста нет: её первый абзац — вход в главу (НП-19, НП-52).
   - **Текст стабилен.** Флаги меняет только исход (`run-state.md`, правило 3), а после исхода игрок уходит из сцены, поэтому условия сцены вычисляются один раз, при входе.
   - У сцены с двумя и более вариантами последний абзац без условия: ставка выбора видна при любых флагах (НП-4; BS-06).

4. **Вариант.** Данные хранит История, смысл полей определяют Выбор и Проверки.

   | Поле | Кто определяет | Правило |
   |---|---|---|
   | `id` | История | уникален в данных героя |
   | `текст` | История | подпись кнопки (форма — НП-5) |
   | `вид` | Выбор (предварительно) | `обычный`, `рискованный` или `безопасный` |
   | `условие`, `причина` | Выбор | показ по флагам и `[причина]`; вариант, открытый прошлым, — вариант с этими полями, а не отдельный вид (НП-24) |
   | `проверка` | Проверки, правило 1 | есть тогда и только тогда, когда `вид` = `рискованный`; `успех` и `провал` — `id` двух исходов |
   | `исход` | История | `id` исхода; обязателен у `обычный` и `безопасный`, запрещён у `рискованный` |
   | `исключение` | История | причина словами; снимает BS-07, BS-08 и предупреждение «более лёгкий вариант» (`d20-checks.md`, Edge Cases; закрывает Open Questions 7 для вариантов) |

   - Каждый исход принадлежит ровно одному варианту.
   - **Линейная сцена** — сцена с единственным вариантом («Нести бога к мосту»). Это не выбор (НП-6), и BS-07 её не проверяет. Исход её варианта может быть без текста: тогда сразу идёт мост следующей сцены.
   - В сцене с рискованным вариантом есть безопасный вариант (`heroes.md`, правило 10); его исход ставит ровно один флаг `price` (`run-state.md`, правило 6). Как цена названа до выбора — НП-7.

5. **Исход.** Поля: `id`; `абзацы` (хотя бы один без условия, кроме исхода линейной сцены; фраза крита — отдельная первая строка, в лимиты не входит, `d20-checks.md`, правило 6); `ставит`, `снимает` — `id` объявленных флагов героя, один `id` в обоих списках — ошибка; `переходы` — упорядоченный список `{если?, переход}`.
   - **Исход применяет Система выбора** (`d20-checks.md`, правило 9): она передаёт `ставит` и `снимает` в Состояние. История флаги не ставит и ничего не применяет, ей принадлежат только данные исхода. Строка `run-state.md`, Interactions («Ветвящаяся история — ставит через исходы сцен») и строка в его Dependencies («запись исходов сцен») этому противоречат и требуют правки (см. Interactions).
   - Текст исхода показывается после применения, поэтому его условия вычисляются по набору флагов после исхода.
   - Один исход на успех и провал сразу запрещён (`d20-checks.md`, Edge Cases). Содержание и планка исходов — НП-36…47.

6. **Переход.** Поля:

   | Поле | Правило |
   |---|---|
   | `id` | уникален в данных героя |
   | `куда` | `сцена:<id>` (в этой главе), `конец_главы` или `концовка:<id>` (`id` из `концовки` героя) |
   | `мост` | только у `сцена`, обязательно: `основа` и `вставки` — список `{если, текст}`; показываются основа и первая вставка, условие которой истинно, то есть не больше одной (НП-9). Место вставки в основе — отметка в тексте, формат — ADR |
   | `кода` | только у `конец_главы`, обязательно: абзацы; последний без условия — фраза-зацепка следующей главы (НП-50, решение владельца 2026-11-13) |
   | `ранняя` | только у `концовка`: «да» — ранняя концовка (правило 11) |

   - **Мост на каждом переходе.** Переход принадлежит одной сцене-источнику: на него ссылаются только исходы этой сцены. Исходы одной сцены, которые сходятся в одну цель, делят один мост и показывают разницу вставкой. Вход из другой сцены — другой переход и другой мост («под вход», НП-9).
   - **Выбор перехода.** Список `переходы` исхода проверяется сверху вниз по флагам после исхода; срабатывает первая запись с истинным `если`; последняя запись без `если` обязательна. Случайности нет.
   - Мост условного перехода называет причину из прошлого (НП-23; проверяет `lore-inquisitor`).
   - У `концовка` нет ни моста, ни коды: дальше идёт карточка концовки.

7. **Условия.** Абзац, вставка моста, запись `переходы`, запись `старты` и `условие` варианта задаются одним языком: вопросы Состояния (`run-state.md`, правило 4) — есть флаг, нет флага, любой из списка, любой флаг категории, какой флаг стоит в группе; связки «и», «или», «не». Флаги не считаются; журнал, броски и прошлые исходы условиями не читаются.
   - Ссылаться можно только на объявленные флаги героя (BS-01). На флаг, который не ставит ни один исход героя, — предупреждение BS-11.
   - Когда вычисляется: абзацы сцены и мост — при входе; абзацы исхода, кода и `переходы` — по флагам после исхода; `старты` — при начале главы. Результат зависит только от набора флагов, поэтому после загрузки он тот же.
   - Условный абзац ничего не ставит. Сколько условных абзацев и читаемых флагов допускает сцена — F4 (из НП-16, НП-28).

8. **Точка возобновления** (автосохранение по сценам, `USER_PREFERENCES.md`, «Доступность»). История отдаёт Сохранению `{глава, сцена, переход входа, ожидающий исход}`. Текст экрана не хранится: он однозначно считается по сцене, переходу и флагам.
   - При входе в сцену ожидающего исхода нет.
   - Вариант без проверки: исход применяется, и снимок берётся в момент касания; ожидающий исход = его `id` (`run-state.md`, правило 11). После выгрузки игрок видит тот же исход.
   - Вариант с проверкой: ожидающего исхода нет. До входа в следующую сцену в сохранении лежат результат броска и набор флагов до исхода; после выгрузки игрок снова на итоге, и по «Продолжить» исход применяется один раз (`d20-checks.md`, правило 9).
   - Для схемы главы (правило 11) Сохранение держит снимки входа в стартовую сцену и в каждую пройденную узловую сцену текущей попытки.

9. **Граф без циклов.** Из сцены нельзя по переходам вернуться в неё же; у любой сцены, кроме вариантов входа, есть входящий переход. Кнопки «Назад» к прошлой сцене нет: бросок окончателен (`d20-checks.md`, правило 8). Возврат по схеме главы ребром графа не считается: это новая попытка из снимка (правило 11), поэтому граф остаётся без циклов. Оговорки о петлях в `d20-checks.md`, формула 7, к этой главе не относятся.

10. **Финалы главы и концовки** (решение владельца 2026-11-13).
    - Финальный узел (`финал`) — узловая сцена хребта; из неё выходят финалы главы. Финалов `FINALES_BASE` + `FINALES_PAST` (F8): базовые достижимы без условий на флаги (обычно успех, провал и безопасный вариант финального узла), открытый — только через вариант с `условие` или условный переход, которые читают прошлые флаги.
    - Финал не последней главы ведёт в `конец_главы`, финал последней — в `концовка`. В MVP глава одна, поэтому её финалы — 3 + 1 концовки (это заменяет «2 разных исхода» из MVP концепта).
    - **Провал цели.** Финал (или исход раньше него) может провалить цель: такой исход ставит `флаг_провала_цели`, и следующая глава начинается со своего варианта входа (правило 2). Глава при этом доходит до финала: тупика нет.
    - Концовку называет сам переход. Флаги выбирают среди концовок только условиями; скрытой суммы и счёта провалов нет (`run-state.md`, правило 4; НП-47).
    - Экрана «Вы погибли, загрузить сохранение?» нет по построению: любой терминал — исход с текстом, а дальше кода или карточка концовки (НП-45).
    - `конец_главы`: показывается кода; затем Цель главы получает сигнал «глава закончена», Состояние снимает флаги `chapter`, и начинается следующая глава по порядку `главы` героя. Если следующей главы нет — ошибка данных. Кода читает флаги `chapter`, потому что показывается до сигнала (НП-50, НП-51).

11. **Ранняя смерть и схема главы** (решение владельца 2026-11-13).
    - Ранняя концовка — переход `концовка:<id>` с `ранняя` = «да». Её даёт только исход `провал`, и только в сцене, которая не входит в варианты входа. Безопасный и обычный варианты в неё не ведут. Число и частота — F5. Ставку называет сцена до выбора (НП-18). Смерть — полный исход и карточка концовки со своей иллюстрацией; Галерея её засчитывает.
    - После карточки открывается **схема главы**. Точки возврата: стартовая сцена, через которую вошли в главу в этой попытке, и каждая узловая сцена, пройденная в этой попытке до сцены с роковой проверкой. Саму роковую сцену схема не предлагает: вернуться в момент прямо перед броском нельзя.
    - **Возврат — новая попытка.** Состояние создаётся заново из снимка входа в выбранную сцену: флаги, журнал и переход входа (тот же мост) — как при том входе; всё, что было после, отбрасывается. Броски новые и честные (`d20-checks.md`, правило 10); ранняя концовка остаётся в Галерее. История сама ничего не применяет.
    - После обычного финала схема главы не открывается.

12. **Инварианты графа** (проверка при сборке; в MVP — вычитка по таблице путей, `d20-checks.md`, AC-33).
    - **Нет тупиков** (BS-03; НП-45). В каждой сцене есть вариант без проверки и без `условие`, открытый при любых флагах и помехах (`heroes.md`, правило 10). У каждого исхода непустой `переходы`, и его последняя запись без `если`. Каждая цель существует. Исход провала не ведёт в сцену своей проверки.
    - **Достижимость** (BS-04). Каждая сцена достижима из одного из `старты` без учёта условий; каждый исход указан одним вариантом; каждый переход — хотя бы одним исходом своей сцены. По флагам (BS-12): место чтения, условие которого не истинно ни на одном пути, — «мёртвое место». Флаг `price`, который читает только эпилог, — предупреждение (ответ на НП, раздел 13, п. 6; ответ на `run-state.md`, Open Questions 2). Мёртвая ветка — F6.
    - **Нет фальшивых выборов** (BS-07, BS-08; проверяемая форма НП-6). *Читаемый флаг* встречается хотя бы в одном условии данных героя (абзац, вставка, вариант, переход, старт, строка эпилога); фишка героя чтением не считается. *След исхода* — читаемые флаги, которые он ставит или снимает, плюс цели его переходов. *След варианта* — след его исхода, у рискованного — пара следов успеха и провала. В сцене выбора след каждого варианта непуст, и следы любых двух вариантов различаются (ошибка, снимает `исключение`). Следы успеха и провала одной проверки различаются (предупреждение).
    - **Узел читает прошлое** (BS-17; НП-15): узловая сцена читает хотя бы один флаг в мосте, абзаце или варианте. Исключение — стартовая сцена первой главы героя.
    - **Ритм** (BS-13; НП-17): между двумя сценами с рискованным вариантом на любом пути есть вдох; линейных сцен подряд не больше предела (F7).
    - **Бюджет проверок и длина пути** (BS-14, BS-15; `d20-checks.md`, формула 7 и Open Questions 11): что считается сценой пути — F2. Нарушение потолка и пола — предупреждение (закрывает Open Questions 6). Путь короче `S_path_min`, который кончается не ранней концовкой, — предупреждение: безопасный вариант не срезает хребет.
    - **Слов на путь** (BS-18) — F3.

13. **Чего в системе нет.** Таймеров; случайных переходов (случайность — только d20); арифметики по флагам; возврата в пройденную сцену, кроме схемы главы после ранней смерти; возврата к моменту перед роковым броском; экрана поражения.

### States and Transitions

Сохраняются `Сцена`, `Проверка`, `Исход` (только после варианта без проверки) и `Схема главы`. Исход проверки в сохранение не попадает: до входа в следующую сцену там лежат результат броска и набор флагов до исхода (`run-state.md`, правило 11). Файл пишет Сохранение.

| Состояние | Переход | Когда | Результат |
|---|---|---|---|
| Нет сцены | → Сцена | новое прохождение или новая глава | выбрана запись `старты` (для первой главы — единственная); текущая сцена — старт, переход входа пуст; снимок входа; показан текст |
| Сцена | → Исход | касание варианта без проверки | Выбор повторно проверяет доступность и применяет исход; снимок до показа текста; текст по флагам после исхода |
| Сцена | → Проверка | касание рискованного варианта | флаги не меняются; дальше ведёт Экран броска (`d20-checks.md`, States) |
| Проверка | → Сцена | «Передумать» или «Назад» до «Бросить» | тот же текст сцены, бросок не потрачен |
| Проверка | → Исход | «Продолжить» на итоге | Выбор применяет исход один раз; текст после отметки «применён» (`d20-checks.md`, правило 9) |
| Исход | → Исход | повторное «Дальше», пока переход не выбран | отклоняется: одно «Дальше» — одна смена |
| Исход | → Сцена | «Дальше»; переход `сцена:<id>` | первая запись `переходы` с истинным `если`; текущая сцена = цель, переход входа = этот переход; снимок входа (для узловой — ещё и снимок для схемы главы); показаны мост и текст сцены |
| Исход | → Кода | «Дальше»; переход `конец_главы` | показана кода по флагам главы (не сохраняется: после загрузки снова `Исход` или `Проверка`) |
| Кода | → Нет сцены | «Дальше» | сигнал Цели главы «глава закончена»; Состояние снимает флаги `chapter`; следующая глава по `главы` героя |
| Исход | → Концовка | «Дальше»; переход `концовка:<id>` | Концовкам переданы `id` и признак `ранняя`; Состояние → «Завершено» |
| Концовка (обычная) | → Нет сцены | «Пройти заново» или выбор героя | История обнуляется |
| Концовка (ранняя) | → Схема главы | карточка закрыта | показаны точки возврата (правило 11); ранняя концовка уже в Галерее |
| Схема главы | → Сцена | выбрана точка возврата | Состояние создано из снимка этой точки; переход входа из снимка; новая попытка |
| Схема главы | → Нет сцены | «Пройти заново» или меню | История обнуляется |
| — | → Сцена / Проверка / Исход / Схема главы | загрузка | `Сцена` — тот же мост и текст; `Проверка` — сохранённый итог, исход по «Продолжить» один раз; `Исход` — текст снова без повторного применения; `Схема главы` — те же точки возврата |

- «Вход» — мгновение между «Дальше» и показом сцены, когда берётся снимок, а не отдельное состояние.
- В `Сцена` и `Кода` флаги не меняются: их меняют только вход в `Исход` и сигнал конца главы.
- Если `id` сцены, перехода или исхода из сохранения нет в данных: **НЕ СДЕЛАНО** (Edge Cases). Договорённость одна: История сцену не угадывает.

Константы вносятся в конфиг и в `design/registry/entities.yaml` с источником в этом GDD.

**F1. Размер и форма главы.** `S_chapter = N_start + S_common + B`; длина пути `scenes(p) = 1 + S_common + b(p)`, где `b(p) ∈ {0, B}` (проходит ли путь через ответвление; ответвление в обход хребта — `b(p) ∈ {B − k, B}`, где k — заменённые сцены хребта). `S_common` — сцены хребта после варианта входа, включая финальный узел.
- Пример, глава 1: `N_start = 1`, `S_common = 10`, `B = 1` → `S_chapter = 12`, пути 11 и 12 сцен (≥ `S_path_min` = 8).
- Пример, глава N+1: `N_start = 2`, `S_common = 9`, `B = 1` → 12 сцен, пути 10 и 11.
- Хребет примера главы 1: `s01` старт (линейная), `s02` П, `s03` в, `s04` П, `s05` в, `s06` линейная, `s07` П, `s08` в, `s09` П, `s10` в, `s11` П финал; П — проверка и узел (5 узлов), в — вдох; ответвление `b1` (вдох) между `s04` и `s05`.

**F2. Что считается сценой пути** (ответ на `d20-checks.md`, Open Questions 11). `scenes(p)` — число посещений сцен на пути p от стартовой сцены до сцены, чей исход ведёт в терминал. Считаются: старт, вдохи, линейные сцены, ответвление. Не считаются: исходы, мосты, кода, карточка концовки. Пути — пути графа, а не попытки: возврат по схеме главы новых путей не создаёт. R(p) и условия `max R(p) ≤ K_budget`, `min R(p) ≥ K_min` для `scenes(p) ≥ S_path_min` без ранних концовок — по `d20-checks.md`, формула 7. В примере F1: R(p) = 5 на обоих путях; потолок 5 ≤ 5, пол 5 ≥ 3; между проверками всегда вдох (F7).

**F3. Слов на путь.** `W(p) = Σ_{s∈p} (W_мост(s) + W_сцена(s, F)) + Σ_{o∈p} W_исход(o, F) + W_кода(p)`, где F — флаги на пути в момент показа, фраза крита не считается, ранние концовки не проверяются. Условие: `W_min ≤ W(p) ≤ W_max` для каждого пути (BS-18). Отсюда средний предел на блок текста: `w̄_max = (W_max − W_мосты − W_кода) / (S_p + O_p)`, где `S_p` — сцены пути, `O_p` — исходы с текстом.
- Пример (путь 11 сцен из F1, MVP, коды нет): 10 мостов × 30 = 300 слов; 9 исходов с текстом (у двух линейных сцен текста нет); `w̄_max = (2000 − 300 − 0) / (11 + 9) = 85` слов на сцену или исход. Сцена 70 слов, исход 90: `W = 300 + 11 × 70 + 9 × 90 = 1880` — в окне.
- Если писать по верхним «типичным» значениям НП, раздел 11 (сцена 3–5 абзацев по 15–45 слов ≈ 140, исход ≈ 110): `W ≈ 300 + 1540 + 990 = 2830` — больше `W_max`. Предел пути срабатывает раньше экранных потолков: при 1500–2000 словах сцена в среднем ≤ ~75 слов, исход ≤ ~95.
- Объём героя для справки: ~25 тыс. слов со всеми ветками (решение владельца) / 4–6 глав ≈ 4,2–6,3 тыс. на главу.

**F4. Лимиты одного экрана** (источник — `USER_PREFERENCES.md`, «Подача на экране телефона», и НП, раздел 11; худший набор флагов — все условия истинны):

| Элемент | Предел | Проверка |
|---|---|---|
| абзац | ≤ 60 слов (по пробелам) | предупреждение |
| мост | 1 абзац ≤ 60 слов; показана ≤ 1 вставка | ошибка за число абзацев, предупреждение за слова |
| сцена на экране (мост + абзацы) | ≤ 6 абзацев | предупреждение |
| условных абзацев в сцене | ≤ 2 | предупреждение |
| флагов, читаемых прозой сцены (мост и абзацы) | ≤ 3 | предупреждение |
| исход | ≤ 6 абзацев (нижний край 3 — вычитка, НП-37) | предупреждение |
| вариантов в сцене / от прошлого в выборе | ≤ `OPTIONS_MAX` / ≤ 2 | ошибка / предупреждение |
| кода | ≤ 3 абзацев | предупреждение |

**F5. Частота ранней смерти.** `P_early = Σ_{t ∈ T_early} P(t)`, где P(t) — вероятность дойти до ранней концовки t при равновероятном выборе среди видимых вариантов и шансах героя: `P_провал = 1 − P_успех`, `P_успех = (21 − (СЛ − бонус)) / 20` в окне 25–75 % (`d20-checks.md`, формула 2). Условия: `P_early ≤ P_EARLY_MAX` и `|T_early| ≤ N_EARLY_MAX` на главу (BS-16).
- Пример: роковой вариант Сила +4 на Трудно 15: `P_успех = (21 − 11) / 20 = 50 %`. Если это один из трёх вариантов сцены, `P_early = 1/3 × 0,5 ≈ 16,7 %` > 10 %: слишком часто. Если вариант открывает флаг, стоящий на половине путей: `0,5 × 16,7 % ≈ 8,3 %`, проходит.

**F6. Мёртвая ветка.** Для каждой сцены и каждого базового финала `P_visit ≥ DEAD_BRANCH_PCT` в той же модели, что F5 (BS-12). Ранние концовки и открытый финал порогом не меряются: они редкие нарочно, их частоту симуляция показывает для справки. Исходы одной проверки тоже не меряются: их держит окно 25 % (`d20-checks.md`).

**F7. Ритм.** На любом пути между двумя сценами с рискованным вариантом не меньше `PAUSE_SCENES_MIN` сцен без него; линейных сцен подряд не больше `LINEAR_RUN_MAX`. Пример F1: «П в П в л П в П в П» — условия выполнены.

**F8. Финалы.** У главы `FINALES_BASE` базовых финалов (достижимы без условий на флаги) и `FINALES_PAST` открытых (только через условие на прошлые флаги). Следы финалов попарно различны (правило 12).
