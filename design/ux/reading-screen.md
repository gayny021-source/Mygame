## Purpose & Player Need

Игрок приходит сюда, чтобы **прочитать историю и выбрать, что герой сделает дальше**. Экран — главный носитель игры: текст, кадр, ставка, варианты и исход (БС:844-895; `game-concept.md:120-129`). Без него нет игры; если он неудобен, ломаются столпы: «Бросок — событие» (выбор должен подводить к броску с известными шансами), «Решения имеют вес» (причина варианта и последствия видны), «Провал — подарок» (страница исхода читается так же, как успех). Фраза: «Игрок приходит на экран, чтобы дочитать до ставки и выбрать вариант, зная шансы».

## Player Context on Arrival

- Приходит: из меню («Продолжить» / новое прохождение), с Экрана броска (после исхода или «Передумать»), по «Дальше» с предыдущей страницы, из загрузки после выгрузки Android (БС:859, 886-889).
- Эмоция (допущение): спокойное, чуть насмешливое чтение с ростом напряжения к ставке; игрок на телефоне 10-30 минут, вероятно, одной рукой (`game-concept.md:244-254`). Не торопим: таймеров нет (ДОСТ M5).
- Приходит добровольно; сюда игра отправляет и после Экрана броска.

## Navigation Position

Корень → Меню/выбор героя → **Экран чтения** (страницы: сцена, исход, кода) → Экран броска / карточка концовки / пауза. Экран контекстный, доступен только внутри прохождения. Альтернативный вход: загрузка сохранения (возобновление на той же странице, БС:886-889; ДОСТ M11).

## Layout Specification

Размеры — на базе 1080×1920, портрет, ширина 1080 одна (БС:837; ЦГ:315; СВ:566). Раскладка держится якорями, а не масштабом: **верх** — зона цели (от верхней вставки Safe Area); **низ** — подсказка «Дочитайте», полоса, затухание и нижняя вставка навигации; **поток** — между ними, получает всю остальную высоту. На 1080×2400 (aspect=expand, `project.godot:23`) лишняя высота уходит потоку, зона и низ не растягиваются; проверка обязательна на обоих разрешениях (решение TD, U1). Отступы Safe Area 96/144/240 px — **предварительно** (ИЛ:150, НЕ СВЕРЕНО); значения берутся из `DisplayServer.get_display_safe_area()` через одну обёртку; Open Q 15 остаётся до замера на устройстве и спеку не блокирует (TD, U4).

**Границы ядра и UI (решение TD, G2/G3).** Спека описывает контракт: любую логику (состояния вариантов, подпись и округлённый шанс, флаг «нет открытых вариантов», защёлку «ставка прочитана», гард «Дальше») владеет ядро (RunSession, StoryScreen); UI только рисует готовые поля. Слова «экран показывает поле X ядра» ниже означают это. Список полей — в разделе Dependencies.

**Режимы мыши (U2, G1).** Таблица `mouse_filter`: поток и текст — PASS (RichTextLabel тела: `fit_content=true`; `ui.md:30-32`); карточки, «Дальше», зона цели, слот кадра — STOP по своей области; акцент-полоса, затухание, слой «Дочитайте до конца», декор — IGNORE; STOP на весь экран — только scrim панели цели и слой просмотра.

### Information Hierarchy

1. Начало моста — первое, что читает игрок (БС:870; AC-67 `БС:1131`).
2. Цель главы (одна строка подписи + точки): «где я» (ЦГ:284-295; ДОСТ M10).
3. Кадр сцены: настроение, не носитель сюжета (ИЛ:43(г)).
4. Ставка и варианты в конце потока (БС:851-852).
5. Открывается по запросу: панель цели с карточкой героя, просмотр кадра на весь экран.

Страница исхода: та же зона цели; в потоке слот кадра (кадр исхода или сцены), строка-контекст, фраза крита, абзацы, «Дальше» (БС:875-895; ИЛ:45, 280).
Кода (VS): зоны цели нет; поток: кадр финального исхода, ≤3 абзацев, зацепка отдельным отступом, «Дальше» (БС:897-905; ЦГ:307).

### Layout Zones

| Зона | Место | Поведение | Источник |
|---|---|---|---|
| Закреплённая зона цели | верх, внутри Safe Area, над потоком | высота не меняется, пока экран показан; потолок 30 % высоты 1920 (576 px), расчётный худший случай ≈516 px на 200 % | ЦГ:287-295 |
| Акцент-полоса героя | левый край закреплённой зоны, всегда видна (решение CEO Q1) | не нажимается, без тени, не кнопка; сторона и ширина — art-director | АБ:200-202; ГЕР:646 |
| Поток прокрутки | под зоной | кадр, текст, ставка, варианты, «Дальше» одним потоком; свайп — единственный жест | БС:852, 951-952 |
| Слой подсказки «Дочитайте до конца» | у нижней границы Safe Area, поверх потока | не в потоке, касаний не перехватывает, текст не прокручивает | СВ:546-554 |
| Нижний отступ потока | под последним элементом | не меньше нижней вставки навигации + высоты полосы (≈55 px при 100 %, ≈110 px при 200 %) | СВ:550, 567 |
| Слои поверх экрана | панель цели, просмотр кадра, пауза | по одному; «Назад» закрывает верхний | ЦГ:300; ИЛ:55(е) |

Запасной вариант зоны (решение CEO Q2): если на 1080×1920 при 200 % начало моста при входе занимает меньше 2 строк (ИЛ:282; БС AC-67), зона сворачивается до одного ряда точек (≥168 px), подпись остаётся в панели. Порядок проверки — замер на макете (ИЛ:159; ЦГ:295).

## Жизненный цикл

Решение TD (G4). Источник событий — ядро (RunSession), UI подписан на сигналы.

| Событие | Что делает экран |
|---|---|
| `loaded(code, screen)` | при `OK` строит поток для `screen`; прокрутка в начале, панель закрыта, титр не повторяется. При ином `code` этот экран **не открывается**: показ экрана ошибки сохранения принадлежит отдельной спеке (Q8), Экран чтения не строится и не получает ввода |
| `show_released` | снимает резерв/рисует страницу; после него стартует защитное окно 300 мс |
| `waiting()` | ядро ждёт записи: UI ничего не считает, касания вариантов отклоняет ядро; `advance()` при `waiting()` отклоняется |
| `NOTIFICATION_WM_GO_BACK_REQUEST` (1007) | по таблице «Назад» (Interaction Map); игру не закрывает (`quit_on_go_back=false`, ДОСТ M12) |
| `APPLICATION_PAUSED` при **незавершённом билете** (запись выбора или броска в ожидании) | сохраняется: то, что ядро уже приняло и записало (выбор, результат «Бросить»; ДОСТ M11); отменяется: прокрутка, панель, просмотр кадра, титр — всё в памяти. **Защёлка «ставка прочитана» в ядре при `APPLICATION_PAUSED` не сбрасывается**: она факт о прочитанном, а не о виде (сбрасывается только на новой сцене); после возврата экран строится заново от снимка возобновления, защитное окно 300 мс |
| Выгрузка экрана | снимает `просмотр_открыт`, гасит Tween, освобождает кадры (ИЛ:59) |
| Ошибка потока (СВ Э-23): после броска `RS.flow_error()` = true, после фейда Экрана броска; без проверки — отказ «не применено» на вариант | рисует «Не удалось продолжить» вместо блока вариантов; защитное окно 300 мс |
| `APPLICATION_PAUSED` / `RESUMED` на «Не удалось продолжить» | тот же экран; новое окно 300 мс от возврата |
| Процесс убит на «Не удалось продолжить» | ничего; после запуска и «Продолжить» из меню — по последнему сохранению (после броска — «Итог показан (восстановлен)», без проверки — сцена и выбор) |

## Dependencies

Спека **зависит от новой истории «Экран чтения: ядро для UI»** (владелец `lead-programmer`; решение TD G2+G3). Пока ядра нет, поля ниже — контракт, а не реализация.

| Поле ядра | Что отдаёт | Кто рисует |
|---|---|---|
| состояние варианта | открыт / закрыт помехой / неактивен (до защёлки) / выбрано / заблокирован | карточка варианта |
| готовая подпись | «Сила +4 · Средне 13 · шанс 60 %» с округлённым шансом, или «Без броска · цена», или «Сила закрыта: причина» | строка подписи |
| флаг «нет открытых вариантов» | bool | запасной экран |
| защёлка «ставка прочитана» | bool; сбрасывается на новой сцене; сохраняется при «Передумать» и при смене темы/размера | подсказка «Дочитайте» |
| вход «строка ставки видна» (UI → ядро) | UI сообщает ядру факт видимости последней строки ставки (вне полосы, затухания, вставки навигации); защёлку по нему поднимает RunSession (владелец) | UI шлёт, ядро решает |
| гард `advance()` | при `waiting()` и повторе отклоняет; `apply_plain`/`choose_check` отклоняют повтор | «Дальше», карточка |

Защёлка (U3): ставка считается прочитанной, только когда её последняя строка попала в видимую область потока **без** полосы подсказки, затухания и нижней вставки навигации. Остальные зависимости — History, Выбор, d20, Цель главы, Иллюстрации, Герои (раздел Data Requirements ниже).

## Performance (решение TD, G5)

- Поток пересобирается только при новом `StoryScreen`; смена темы или размера перестраивает вид из той же модели.
- Смена состояния варианта (например, инверсия «выбрано», блокировка) обновляет свойства карточек, без пересборки потока.
- Кэш текстур кадров ≤2 (действующий и «на шаг вперёд»); освобождение прежнего при смене.
- Перед новым фейдом/появлением прежний Tween убивается.
- Заметки реализации: `load_threaded_request` для кадров; затухание и защёлка по сигналу прокрутки, не в `_process`.
